# ADR-0005: Muse is the only independent QA source; local gates never substitute

- Status: accepted
- Date: 2026-10-28

## Context

The acceptance contract requires independent black-box QA and reserves release authority to the user. A self-run test suite cannot demonstrate independence, and a template cannot demonstrate that a test happened.

## Decision

- The real Muse transport is the household task queue at `http://<queue-host>:9110`, accessed only through `queue_client.py --role producer --producer claude`, with dedicated credentials in `private/credentials.json`. Recipients are `muse-1`, `muse-2`, `muse-3`.
- Every gate produces `qa/handoff-Gn.json` and must receive `qa/muse-verdict-Gn.json` from Muse on the same commit and run id. Claude never writes a verdict file.
- `qa/muse-transport.json` records the discovered transport, the probe evidence, and the availability state. If the queue is unreachable, the state is `MUSE_UNAVAILABLE` and gates stay blocked.
- A failed gate requires a new commit and a full re-run on that commit; old verdicts are not reused.
- `python scripts/check_gates.py --root .` validates the evidence contract only. It cannot authenticate Muse or real hardware, and passing it is not a claim of quality.
- Release sequence: local G1–G5 pass, user signs `qa/user-acceptance.json`, user provides an empty private repository URL and explicit push consent, only then push. Public visibility, GitHub Release and the AIMetaPhD list are separate authorizations.

## Consequences

- Development can continue while Muse is unreachable, but the deliverable is reported as a technical candidate, not an accepted release.
- Any test evidence generated by Claude is labelled as self-test even when it uses the same scripts Muse will run.
- Gate evidence may contain paths and machine names; it is reviewed for secrets before any push.

## Transport note (2026-10-28)

The queue was reachable and all three consumers were polling; `/health/consumers` and a canary task dispatch succeeded. The queue intermittently stops answering while it processes a large listing, so probes use short timeouts and are retried. See `qa/muse-transport.json`.
